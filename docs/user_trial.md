# Real applicant trial — ready to conduct, not completed

Use a consenting MBA applicant and their own resume, or the fictional sample if they do not want to share personal data with the configured provider. Do not record personal details in submission evidence without permission.

Ask them to find one West Coast healthcare/technology strategy role, explain two supporting resume facts and one unresolved requirement, save it with a follow-up, and fill the practice form. Time from opening the app to completing each task. Record errors, corrections, fields filled accurately, and whether they understand that the score is not a hiring probability. Compare the same tasks manually using the same source posting and resume, alternating task order if more than one person participates.

Record actual observations and exact feedback, not expected responses. Do not submit an employer application or accept employer terms during the trial. A controlled form does not measure real Workday completion time.

| Measure | Actual observation |
| --- | --- |
| Participant role and consent | Not collected |
| Manual task time | Not measured |
| App-assisted task time | Not measured |
| Fields requiring correction | Not measured by a human |
| Did they notice an eligibility gap? | Not observed |
| Exact feedback | No quote collected |

Automated checks in `output/evidence/` are functional evidence only. Keep this status explicit until a person actually tries the app.

## Ready-to-use worksheet
Open `output/user_trial.html` by double-clicking. It provides manual/app timers, correction counts, a place for an observed qualification gap and exact feedback, and an anonymous JSON download. It sends nothing to a server and does not contain default results. Complete both rounds and review private details before sharing the export. The worksheet itself has been tested; no real participant result has been created.
